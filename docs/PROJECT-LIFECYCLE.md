# 프로젝트 등록부터 실제 화면 사용까지의 검증 기준

Issue #60은 개별 단계 검사만으로 전체 동작이 검증됐다고 판단하던 공백을 보완한다. 아래는 현재 구현과 검증 경계다. 마지막 CI·배포 결과는 연결된 PR에 정확한 커밋으로 기록한다.

| 경로 | 실제 구현·검증 | 확인 범위 |
| --- | --- | --- |
| 프로젝트 만들기 | 브라우저 폼 → 실제 로컬 서버/Auth/DB → 다시 조회 | 합성 프로젝트, 개인 영역 |
| GitHub 연결 | 기존 저장소 주소를 같은 프로젝트의 서비스로 등록 | 저장소가 없으면 등록 필요와 바로 등록 버튼 표시 |
| GitHub 저장소 신규 생성 | 미구현 | GitHub에서 만든 저장소를 등록해야 함 |
| 실행기 자동 발견 | 프로젝트 생성 전 연결한 실행기가 기존 설정 그대로 새 프로젝트 발견 | 삭제된 예전 프로젝트 ID가 있어도 현재 영역에서 발견, 다른 영역 차단 |
| 작업 요청·응답 | 실제 브라우저 요청 → 실제 claim/lease → 실제 Git 체크아웃 → Codex 호출 계약 → 서버 결과 → 화면 자동 갱신 | GitHub API와 Codex 출력은 합성. 실제 구독 호출 성공으로 판정하지 않음 |
| 실행기 다시 연결 | 보관된 HttpOnly 기기 쿠키를 새 실행기 클라이언트에서 재사용 | 프로젝트별 재설정 없이 다음 요청 처리 |
| 화면 준비·열기 | 실제 runner → Docker → 실제 터널 프로세스 계약 → HTTPS → 서버에 보관된 결과 → 실제 `/api/preview/open` 서명 → 승인 기기 화면 | 외부 Cloudflare 전송만 로컬 공급자 fixture. 실제 운영 인터넷 경로와 구분 |
| 앱 초기화·저장 | 화면 제목과 API 초기값 확인 → 쓰기 → 새로고침 → 값 유지 | 별도 임시 앱 데이터. 원본의 합성 기존 데이터는 그대로 보존 |
| 정적 웹 | 실제 모듈 파일 로드 후 렌더링과 브라우저 저장·새로고침 | HTML 응답만으로 검사 통과하지 않음 |
| npm 앱·Vite | 실제 Docker에서 앱 실행, Vite 설정 캐시 쓰기와 이미지 읽기 전용 보존 | 의존성 없는 합성 실행 파일. 실제 선택 앱 소스 검증은 별도 로컬 기록 |
| 단독 Node | `server.js/mjs/cjs` 우선 실행, API와 임시 설정·데이터 초기화 | 실제 Docker/API/저장·새로고침 |
| 최근 수정본·PR | 같은 프로젝트·저장소·PR의 고정 SHA 선택, 변경되거나 닫힌 PR 거부, 검증 실패 시 게시/병합 차단 | 실제 Git + 합성 GitHub 응답. 실제 원격 저장소 쓰기는 CI에서 하지 않음 |
| 실패·재개 | 응답 유실·재시도·취소·오래된 lease·실행기 버전/기능·앱 CLI 호환성 거부 검사 | 요청/선택 SHA/과거 결과 보존, 실패를 성공으로 바꾸지 않음 |
| 접근·만료·중단 | 복사한 주소 거부, 기기 해제 거부, 만료·영역 밖 거부, 터널 중단 시 열기 실패 | 실제 로컬 승인 상태·서명·HTTPS. 운영 자료를 테스트로 수정하지 않음 |
| Mac 설치·재시작 | 파일 해시·설정 보존·LaunchAgent 실패 복구·symlink 시작 검사 | macOS 실제 재부팅/절전·사용자 구독은 Linux CI로 입증하지 않음 |
| 실행기 업데이트 | 기존 수동 업데이트 방식 | 자동 업데이트 미구현. 이 점검은 실행기 버전을 추가로 올리지 않음 |

## 연결된 검사 실행

`npm run test:server`의 마지막 검사는 `tests/support/project-lifecycle.mjs`를 반드시 실행한다. 임시 기기 승인 외에는 프로젝트·서비스·요청·준비 완료 결과를 서버 DB에 직접 주입하지 않는다. 프로젝트와 요청은 브라우저에서 만들고, 실제 실행기가 실제 API로 결과를 보관한다. 브라우저가 자동으로 결과를 받은 다음 새로고침 복원도 확인한다. GitHub 전송은 로컬 합성 Git 저장소, 구독 출력은 실제 Codex 인자의 합성 응답, Cloudflare 전송은 로컬 TLS/CONNECT 및 터널 프로세스 계약으로 한정한다. 예상하지 않은 외부 주소는 거부한다.

이 검사는 기존 필수 CI `server-storage` 작업에 포함된다. 실패하면 동일 작업이 실패하며, 재시도나 준비 완료 결과 주입으로 통과시키지 않는다. 합성 정상·실패 화면은 `test-results/project-lifecycle-*.png`로 보관한다. 기존 `test:automation`, `test:domain`, `test:e2e`, `test:storage`, `test:preview`, `test:remote-preview` 검사도 유지한다.

## 완료로 말할 수 있는 범위

코드 수정, CI 성공, 배포 준비, 실제 사용자 Mac 적용, 실제 구독 응답은 각각의 증거로 판정한다. 설치 성공이나 heartbeat는 앱 기능 성공의 근거가 아니다. 새로운 앱 유형·필요한 환경변수·외부 API·기기 기능은 해당 조건으로 검사하기 전까지 지원/성공을 단정하지 않는다. 실제 사용자 앱 소스를 검사할 때는 허용된 범위에서 격리 실행하고 원본 코드·설정·운영 기록을 보존하며 CI/공개 저장소에 올리지 않는다.
