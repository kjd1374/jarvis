# Jarvis 제품 목적과 구현 상태

2026-10-14 사용자의 최신 요구를 기준으로 한다. 이전의 대화 중심 홈은 `/assistant`로 유지하고, 최근 적용한 네이비·블루·바이올렛 디자인을 재사용한다. 화면에 표시되는 연결 상태와 이 문서의 계획을 실제 구현과 혼동하지 않는다.

## 목적과 화면 순서

Jarvis는 회사 업무·개인 프로젝트·메모와 생각·AI 활용을 한곳에서 관리하는 개인 업무실이다. 실제 작업은 v4 등 별도 서비스에서 수행한다. Jarvis는 진행 상황·결과·분석·다음 행동에 필요한 참조를 모으고, 메모·수정 요청을 관리하며 서비스를 연다. 원본 업무 데이터는 원래 서비스가 관리한다.

화면은 현재 상황 → 필요한 행동 → 상세 정보 순서다. 홈은 오늘/기한 지난 업무, 결정·검증 요청, 연결 문제, 빠른 메모, 자주 쓰는 서비스, 최근 결과를 먼저 보여준다. 프로젝트 상세는 목표·현재 상태·다음 행동, 결과·업무·자료, 서비스·요청·메모를 묶는다. 동기화 기록·맥락 수정 이력·질문 처리 기준은 접어서 확인한다. 메뉴는 업무실·업무·프로젝트·자료실·맥락·설정을 유지한다. 요청은 업무의 하위 보기이고 자료 검색·AI 질문은 별도 바로가기다.

v4는 회사 전용이다. 회사/개인 영역은 UI뿐 아니라 저장 요청, 서버 검색, AI 근거 조회에서 명시적으로 제한한다. 두 영역을 함께 검색하는 기능은 제공하지 않는다. 전체 백업은 사용자가 범위를 직접 선택할 수 있다.

코드가 구현됐다는 사실은 운영 서비스가 연결됐다는 뜻이 아니다. 운영 화면에 합성 결과나 예시 AI 답변을 넣지 않는다.

## 저장과 이관

기본 저장은 같은 주소·브라우저의 IndexedDB `jarvis-workspace` v1이다. 기존 배열에 새 컬렉션을 기본값으로 보충하며 DB를 초기화하지 않는다. 브라우저/배포 주소가 바뀌어도 원래 기록은 남는다. 설정에서 먼저 백업을 내보내고 새 주소에서 검토 후 가져온다. ID 충돌은 기존 항목을 유지하고 개수를 알린다. 다른 영역의 동일 ID·다른 원본 파일 충돌은 병합을 거부한다. 파일 원본 추가와 메타데이터는 원자적으로 저장한다.

서버 저장은 인증된 사용자별 `jarvis_spaces(owner_id, space)` 행에 메타데이터 스냅샷을 저장한다. 서버가 검증한 사용자 ID만 사용한다. 저장은 예상 revision이 현재와 맞을 때만 수행한다. 다른 기기 자료를 검토·병합한 뒤 명시적으로 올리며 자동 덮어쓰기/양방향 동기화는 하지 않는다. 인증·운영 마이그레이션 적용·환경 플래그 활성화는 별도 결정이다. 설정에 연결 필요 이유를 표시하며 로컬 기능은 계속 쓸 수 있다. 상세: `STORAGE.md`.

자료실은 원본 링크와 연결 정보를 먼저 등록할 수 있다. 사용자가 파일을 직접 올리면 브라우저에 원본을 보관한다. 클라우드 활성화 시 명시적 업로드와 사설 다운로드를 사용하며 공개 파일 URL을 만들지 않는다. 서버 원본 전송 실패는 메타데이터 성공과 구분한다.

## 연결·요청·AI의 정직한 상태

- 바로가기 등록 / 읽기 연동 / 작업 실행은 별개다. 현재 등록 폼은 웹 바로가기와 회사 v4 읽기 연결 준비만 제공한다. 실행 연결은 제공하지 않는다. 로컬 프로그램을 웹 주소로 실행하지 않는다.
- 요청 상태는 등록·실행 대기·진행·검증 대기·완료·실패다. 현재는 사용자가 서비스에서 직접 수행한 작업의 상태를 기록한다. 등록/메모 저장은 실행이 아니다. 완료 기록은 검증 내용과 직접 확인 동의가 필요하며 사용자 확인임을 표시한다. 자동 승인·외부 수정 API는 없다.
- 수집 사실에는 서비스/원본 ID/원본 링크, 영역/프로젝트/후속 업무, 상태, 원본 변경·수집 시각을 보관한다. 성공한 완전 응답의 삭제만 반영하고 실패·불완전 응답은 마지막 정상 자료를 유지한다. 재연결·재수집은 같은 서비스+원본 ID를 갱신한다. 재시도 예정 기준은 기록하지만 자동 스케줄러는 아직 없다.
- AI 검색은 허용된 영역/프로젝트의 사실·내 메모·맥락을 조회한다. 자료 종류와 변경·수집 시각, 24시간 이상 경과·동기화 오류를 표시한다. 현재는 키워드 근거 검색이며 자연어 답변 모델은 연결되지 않았다. `/api/assistant/answer`도 근거만 반환하고 501 연결 필요로 응답한다.
- 자료의 문장은 지시·실행 승인으로 취급하지 않는다. 실행 권한은 항상 false이며 실제 검증 전 완료를 주장하지 않는다. 향후 AI 추론은 출처의 사실·사용자 메모와 별도로 저장해야 한다.

## 다음 연결 순서

2026-10-15 사용자는 로컬 직접 연결보다 **웹 v4 연결을 우선**하기로 했다. 앞으로의 개발 작업은 **GitHub를 통한 기록과 변경 추적**을 기준으로 한다. 이전 미커밋 구현을 보존해 작업 브랜치/PR로 정리했고, 사용자가 push·미리보기 이후 **main 병합·프로덕션 배포까지 승인**했다. 현재 개발 중인 합의된 코드 변경은 검증·GitHub 기록·병합·정식 배포까지 진행한다. GitHub 반영과 실제 배포 완료는 각각 확인하고, 새 유료 서비스·인증/접근 확대·운영 DB 활성화·원본 업무 데이터 변경은 코드 배포와 구분한다.

1. 앱 계정 식별 방식과 운영 저장 활성화를 별도 결정한다. 무인증 공개 DB 정책으로 대체하지 않는다.
2. 2026-10-15 제공된 v4 저장소(33m2-v4-workspace)의 main을 검토했다. 기존 인증/조회/집계 구조는 재사용할 수 있으며 전용 읽기 역할과 최소 필드 API는 v4 별도 변경 제안이다. 아직 v4를 수정하거나 연결하지 않았다. 근거·변경 목록은 `integrations/v4.md`에 있다.
3. 읽기 어댑터와 스케줄러를 연결하고 실제 동기화 검증을 수행한다.
4. AI 모델·비용·개인정보 전송 범위를 정한 후 현재 근거 계약에 실제 답변을 붙인다. 실행/코드 수정은 대상·변경 내용과 별도 승인 절차가 갖춰진 뒤다.

Mastra·LangGraph·Codex App Server·TTS·별도 분석 서버는 보류한다. 처음에는 로컬 코드로 보관했고 이후 보호된 고정 미리보기에 반영했다. 현재는 사용자가 코드의 push·main 병합·프로덕션 배포를 승인했다(`DEPLOYMENT.md`). 운영 설정/인증/데이터 변경까지 자동으로 포함하지 않는다.

## GitHub 기반 진척 관리 방향 (2026-10-15)

사용자는 GitHub의 개발 기록과 메모를 AI가 자동 조회해 완료/진행/예정/보류를 정리하고, 다음 작업을 승인 대기로 올리는 흐름을 원한다. 이 자동 조회·AI 판정·실행 기능은 아직 구현하지 않았다.

- 작업 항목(Issue): 목적·해야 할 일·완료 조건·우선순위·선행 작업을 기록한다. 사용자 메모와 결정 변경도 연결한다.
- 코드 변경(PR/commit): 해당 작업과 연결하고 검증 결과를 남긴다. 테스트와 배포 결과도 근거로 조회한다.
- Jarvis: 허용된 저장소별로 GitHub 사실·조회 시각·원본 링크를 저장하고, AI의 상태 판단/다음 작업 제안과 구분한다. 회사/개인 저장소는 해당 영역에 매핑한다.
- 완료 판정: 커밋/메모만으로 완료하지 않는다. 작업의 완료 조건에 따라 구현·검증·병합·배포를 구분한다. 배포가 필요한 작업은 코드 검증만 통과한 상태와 분리한다.
- 보류/순서 조정: 선행 작업 미완료 등 합의된 규칙은 자동 반영할 수 있다. 사유와 변경 이력을 남기고, 우선순위 판단이 불명확하면 사용자 검토로 올린다.
- 승인 대기: 다음 작업의 대상·변경 범위·필요한 권한·검증 방법을 보여준다. 승인된 범위에서만 실행하며, 저장소 본문/일반 메모를 실행 승인으로 취급하지 않는다. GitHub 상태 변경과 실제 코드 실행/병합/배포의 권한도 구분한다.

조회 자동화는 향후 GitHub 변경 알림과 재조회로 구현할 수 있다. 새 대규모 에이전트 프레임워크 도입을 전제로 하지 않는다. GitHub는 개발 기록의 기준이고 실제 고객/업무 데이터는 v4·시트 등 원래 서비스에 보관한다.

## 2026-10-15 연결 준비 업데이트

홈의 `연결 준비`에서 설정 `/settings#connections`로 이동한다. 현재 영역·프로젝트를 표시하고 v4 웹(회사만), GitHub 저장소, 구글 시트 등록 양식을 제공한다. 등록은 기존 서비스 저장/프로젝트 연결을 재사용하며 자동으로 사용자 기록을 생성하거나 기존 자료를 덮어쓰지 않는다. 같은 영역·프로젝트의 같은 주소는 중복 등록하지 않는다. GitHub·시트는 바로가기, v4는 읽기 연결 준비로 저장한다. 읽기 성공 시각을 만들어 넣지 않는다.

설정에 GitHub 완료 판정·보류·다음 작업 승인 기준과 하나씩 연결하는 순서를 기록했다. v4 주소와 저장소는 사용자가 제공한 값으로 채운다. GitHub·시트는 영역과 프로젝트에 맞는 실제 주소를 사용자가 확인해 입력한다. 서비스 카드에서 웹과 GitHub 기록을 각각 열 수 있다. 등록과 열기는 동작하지만 GitHub 자동 조회, AI 진척 판정, 시트 읽기/쓰기, v4 데이터 수집은 여전히 미연결이다.

구글 시트는 먼저 한 시트의 미처리 항목을 읽는 방식부터 검토한다. 원본 항목의 고유 ID를 사용하고 전송할 탭·허용 열·값을 미리 확인한다. 전송 직전 원본 변경을 확인하고 쓰기 후 재조회로 검증한다. 행 번호만으로 대상을 고정하지 않는다. Jarvis에서 확인한 이력과 원본 업무 상태는 별도이며 과거의 시트 열람 여부를 추정하지 않는다. 비공개 시트의 iframe 편집을 보장하지 않고 현재는 원본 새 탭 열기를 제공한다. 실제 Google 인증과 쓰기 권한 확대는 별도 확인한다. 상세는 `integrations/google-sheets.md`, GitHub 단계는 `integrations/github.md`에 정리한다.

## 2026-10-15 서버 보관·기기 연결 승인

사용자가 서버 저장을 승인한 뒤 이메일/로그인은 제외하도록 정정했다. 로그인/가입 화면 없이 처음 기기를 확인하고 이후 세션으로 자동 연결한다. 미등록 기기에는 확인 요청 번호만 보이고 자료는 노출하지 않는다. 기록은 승인된 기기만 같은 개인 업무실 서버에서 불러오며, 회사/개인 조회·검색·파일·AI 근거의 범위 구분을 유지한다. 기존 브라우저 v1 자료는 확인 후 이관한다.

정상적인 저장은 서버 완료 상태로 확인한다. 전송 실패/대기/충돌은 별도 표시하고 로컬 사본을 보존한다. 상세 충돌은 설정에서 필요할 때 확인한다. 실제 AI/v4/시트 연결이나 실행 기능을 새로 켜는 변경은 아니다. 실제 운영 적용과 최초 사용자 기기 확인 결과는 Issue #6에 기록한다. 이전에 없어진 번역 프로젝트가 자동 복구됐다고 주장하지 않는다.

## 2026-10-15 프로젝트·설정의 연결 등록 통합 (Issue #9)

프로젝트 상세의 **연결 서비스**와 설정의 **연결 준비**는 같은 `services` 기록 및 등록/수정 화면을 사용한다. 프로젝트 수정에서는 이름·설명·현재 상태·다음 행동만 편집한다. GitHub/웹 주소를 별도로 재입력하지 않는다. 프로젝트에서 등록하면 해당 프로젝트에 소속되고 설정에서도 표시된다. 설정에서 소속 프로젝트를 지정하면 프로젝트 상세에도 같은 기록이 나타난다. 영역 공통은 특정 프로젝트에 속하지 않으며 회사/개인 범위는 유지한다.

GitHub 전용 양식은 주소를 한 번만 입력한다. 웹 서비스와 GitHub 저장소를 함께 가진 연결도 설정 GitHub 목록에서 찾을 수 있고, 그 목록의 링크는 저장소를 연다. 설정에서 기존 연결을 바로 수정할 수 있다. 같은 영역·프로젝트의 URL 및 동일 GitHub 저장소(.git/대소문자/끝 슬래시)는 중복 등록하지 않는다. 서로 다른 웹 배포가 같은 저장소를 사용하는 경우는 허용한다.

이전 프로젝트의 `repositoryUrl`/`serviceUrl`은 유효한 주소를 공통 연결 목록으로 해석한다. 일치하는 기존 연결을 재사용하고 ID·요청·수집 이력을 삭제하거나 합치지 않는다. 상충하는 서로 다른 주소는 모두 유지한다. 예전 원문 필드는 보관본으로 남기고 현재 주소는 서비스 기록에서만 수정한다. 잘못된 예전 주소를 실행 링크로 만들거나 비밀값이 포함된 원문을 화면에 표시하지 않는다. 다음 일반 저장에서 통합된 JSON을 원자적으로 보관하며 별도 운영 DB 마이그레이션은 없다.

이 통합은 주소 등록·열기·저장 기능이다. GitHub 자동 조회, AI 판정, v4/시트 데이터 연동이나 외부 작업 실행을 활성화하지 않는다.

설정의 **웹 서비스**에는 GitHub/v4/시트로 분류되지 않는 일반 웹 연결도 표시한다. 저장소 없는 웹도 프로젝트·설정에서 같은 ID로 관리한다. GitHub와 웹을 함께 등록한 연결은 GitHub 목록에서 저장소와 웹을 각각 열 수 있다.

## 2026-10-15 GitHub 읽기·구독 CLI 분석 (Issue #11)

사용자의 구현 요청 및 기존 웹 구독 재사용 요청에 따라 공식 Codex CLI 실행기를 추가한다. 위의 GitHub 미구현 설명은 당시 기록이다. 현재 GitHub 등록은 점검 요청을 저장하며, 승인된 로컬 실행기가 gh로 파일 구조·선택 코드·이슈·PR·검증·배포 기록을 읽고 구독 로그인한 Codex로 근거 있는 분석/작업 제안을 생성한다. 프로젝트·설정에서 사실/AI 판단/채택 대기를 구분한다. 자동 점검은 실행기가 켜져 있을 때 15분 간격이고 브라우저는 서버 결과를 갱신한다. 구독 로그인·실제 사용자 실행기가 준비되지 않았다면 연결 대기로 표시한다.

별도 API 키/과금 자동 전환·새 DB/인증 정책·원본 서비스 쓰기·코드 자동 수정/실행은 없다. v4 업무 데이터 상태와 GitHub 점검 상태는 독립적이다. 제안은 사람이 채택해 Jarvis 할 일로 등록하며 완료 제안은 근거 직접 확인을 요구한다. 일반 `/assistant` 자연어 응답은 여전히 미연결이다. 전체 코드 실행/무제한 전체 파일 분석을 주장하지 않으며 조회 범위와 누락을 표시한다. 상세 설정·한도·전송 자료·검증 경계: `integrations/github.md`.

## 2026-10-15 실제 화면으로 이어가는 프로젝트 바로가기 (Issue #13)

프로젝트 제목 아래에 현재 영역·해당 프로젝트의 공통 연결을 사용한 **웹 화면 열기 / GitHub 열기 / 수정 요청 남기기**를 표시한다. 웹 주소가 없으면 상단 **웹 화면 연결**에서 해당 프로젝트로 등록한다. 설정·연결 서비스에서 주소를 수정하면 상단도 같은 기록을 표시한다. 여러 웹은 서비스 이름, 여러 저장소는 소유자/저장소 이름으로 구분하며 같은 저장소는 한 번 표시한다. 영역 공통·다른 프로젝트·반대 영역·이전 주소 보관본은 상단 링크에 포함하지 않는다.

실제 웹/저장소는 새 탭에서 열고, 화면을 확인한 뒤 수정 요청과 검증 기록을 이어간다. 웹 주소 등록은 배포 성공 판정·인증 연결·AI의 웹 화면 관찰을 뜻하지 않는다. GitHub 읽기와 AI 제안은 기존 CLI 실행기가 준비돼야 수행하며 프로젝트 설명·현재 상태·다른 서비스 연결을 임의로 확정하거나 덮어쓰지 않는다. 저장소에 있는 배포 주소 자동 발견/확인 제안과 AI의 실제 브라우저 관찰은 별도 후속 기능이다.
