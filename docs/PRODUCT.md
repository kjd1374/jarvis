# Jarvis 제품 목적과 개발 기준

이 문서는 사용자가 설명한 제품 목적을 보존한다. 기능 제안과 구현은 이 기준을 먼저 읽고 진행한다.
현재 배포된 메뉴와 화면은 임시 레이아웃이며, 제품 요구사항을 대신하지 않는다.

## 사용자가 정의한 목적

Jarvis는 **내가 하는 모든 일을 한곳에서 관리하고, 필요하면 AI가 실행까지 도와주는 통합 업무실**이다.
업무 맥락이 계속 쌓이고 실제 일이 끝나는 개인 업무 시스템을 만든다.

핵심 목표는 다음 다섯 가지다.

1. 출근해서 켜면 오늘 할 일, 진행 상황, 내 결정이 필요한 일이 보인다.
2. 회사 업무, 개인 프로젝트, 메모·아이디어, 파일·결과물을 한곳에서 연결해 관리한다. 회사와 개인 자료는 구분한다.
3. 생각을 적으면 관련 자료와 연결하고, 기획·할 일·실행으로 이어갈 수 있다.
4. 간단한 일은 CLI로 AI를 바로 사용한다. 복잡한 일은 계획 → 실행 → 검수 → 보완까지 맡기며, 중단돼도 이어서 진행한다.
5. 화면에는 결과 요약과 내가 할 선택을 보여준다. 상세 과정은 원할 때 펼쳐본다.

기존 **v4는 회사 통화·고객관리 기능으로 연결**한다.
여러 AI가 대화하는 협업툴을 제품 목표로 삼지 않는다.

## 확정된 범위와 현재 상태

- 한 사람이 사용하는 시스템이다. 로그인 화면, 가입, 팀 관리 기능은 개발 범위에서 제외한다.
- 현재 디자인은 유지한다. 사용자는 추후 더 무게감 있는 디자인을 선호한다고 밝혔다.
- 업무와 자료를 회사·개인 영역으로 구분하고, 항목과 AI 실행에 해당 영역을 함께 보존한다.
- 홈 화면의 우선순위는 오늘 할 일, 진행 상황, 사용자 결정 대기다.
- AI의 실행 과정과 대화 로그는 상세 보기로 두고, 결과와 선택을 먼저 보여준다.
- 현재 구현 범위는 아래 '이번 구현 상태'에 기록한다.
- Supabase와 Vercel의 기존 Jarvis 프로젝트를 재사용한다.

## 추가로 확정된 화면 요구사항

- AI agent처럼 사용할 대화창을 업무실 화면에 둔다.
- 전체 업무 맥락을 계속 보관하고 수정할 수 있는 기능을 둔다.
- 자료실에서 파일을 프로젝트나 업무에 연결할 수 있게 한다.
- 화면 배치가 이 흐름에 맞도록 수정한다. 기존 색감은 유지한다.

### 이번 구현 상태

업무실은 오늘 할 일·진행 중·결정 대기 요약, 중앙 대화창, 누적 맥락·자료·업무 패널로 구성한다.
회사·개인 선택과 프로젝트 범위는 화면 전체에 적용한다. 모바일에서는 대화와 맥락·자료를 전환한다.

대화 기록, 맥락과 수정 이력, 프로젝트·업무, 파일 원본과 연결 정보는 IndexedDB에 저장한다.
새로고침 뒤 복원하며 같은 브라우저의 다른 탭에도 반영한다. 대화에서 맥락 추가와 업무 생성이 가능하다.
회사·개인 영역을 바꾸면 입력 중인 대화와 선택 자료는 초기화해 이전 영역의 내용이 섞이지 않게 한다.

**현재 보관 범위는 같은 브라우저다.** Supabase 서버 동기화, 실제 AI 응답·CLI 실행,
자동 맥락 요약, 파일 본문 추출·검색과 v4 연결은 아직 구현하지 않았다.
사용자가 수정한 맥락과 원본 대화는 저장하며, AI가 맥락을 해석·업데이트했다고 표시하지 않는다.
Supabase의 공개 읽기·쓰기 정책을 추가하지 않고 기존 데이터베이스는 유지한다.

## 제안하는 첫 개발 범위

첫 단계는 **회사·개인을 구분해 생각과 할 일을 저장하고, 오늘 화면에서 진행과 결정을 확인하는 흐름**을 완성하는 것이다.
아래는 사용자의 목적에서 도출한 개발 제안이며, 이미 구현된 기능이나 사용자가 확정한 세부 명세가 아니다.

### 1. 업무 맥락을 보존하는 데이터 기반

- 회사·개인 영역, 프로젝트, 작업, 메모·아이디어를 저장한다.
- 각 항목에 영역을 지정하고, 프로젝트·자료·다른 항목과 연결할 수 있게 한다.
- 파일·결과물의 참조와 활동 이력을 연결할 기반을 둔다.
- 마감일, 진행 상태, 결정 대기 사유를 실제 데이터로 관리한다.

### 2. 첫 사용 흐름

1. 회사 또는 개인 영역에서 생각이나 할 일을 입력한다.
2. 저장한 메모를 작업으로 연결하고, 프로젝트·관련 자료를 지정한다.
3. 작업에 일정과 상태를 부여한다.
4. 홈에서 오늘 할 일, 진행 중인 일, 내 결정이 필요한 일을 확인한다.
5. 작업을 완료하거나 결정을 기록하면 홈과 활동 이력에 반영된다.
6. 새로고침하거나 다시 접속해도 내용과 연결 관계가 유지된다.

이 단계에서는 회사·개인 구분, 저장, 연결, 홈 집계가 실제로 동작하는지 검증한다.
AI 실행 기능은 별도 단계에서 붙이며, 첫 단계에 가짜 실행 결과를 표시하지 않는다.

## 이후 개발 순서 제안

### AI 실행과 이어서 진행

간단한 CLI 요청과 복잡한 실행을 같은 업무 항목에 연결한다.
복잡한 실행에는 계획, 실행 단계, 검수 결과, 보완, 결과물, 결정 요청을 저장한다.
실행 상태와 완료 지점을 보존해 중단 이후에도 이어서 진행한다.
재개할 때 이미 완료한 외부 작업이 중복 실행되지 않도록 식별자와 완료 기록을 관리한다.

홈에는 요약, 진행 상태, 다음 선택을 표시하고 실행 로그는 펼쳐보기로 제공한다.
Vercel 웹 화면과 긴 CLI 실행은 분리하며, 실제 실행 환경과 AI 도구는 연결 단계에서 확인한다.

### v4 연결

기존 v4를 회사 영역의 통화·고객관리 모듈로 연결한다.
고객과 통화의 원본 식별자를 보존하고, 해당 자료를 프로젝트·작업·실행 결과에 연결한다.
v4의 현재 저장소, 실행 방식, 데이터 구조와 제공 API를 확인한 뒤 구체적인 연결 방식을 정한다.

### 자료와 맥락의 확장

파일·결과물 관리와 관련 자료 찾기를 확장한다.
기록한 생각을 관련 맥락과 연결하고 기획, 작업, AI 실행으로 이어가는 흐름을 개선한다.
무게감 있는 시각 디자인의 개편은 별도 요청에 맞춰 진행한다.
