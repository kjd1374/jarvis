# 업무실 사용 흐름 — 2026-10-26

업무실은 짧게 기록하고, 서비스별 업무·현황을 확인하는 공간이다. 큰 메모 카드 아래 할 일·프로젝트·서비스·진단을 계속 붙이던 배치를 두 영역으로 정리한다.

| 영역 | 기본 화면과 행동 |
| --- | --- |
| 범위·저장 상태 | 회사/개인과 저장 상태를 짧은 상단 줄에 유지. 시트 업무로 바로 이동 |
| 빠른 메모·저장 기록 | 상단의 한 영역에서 입력과 최근 기록을 나란히 표시. 검색·전문 읽기·모아보기·저장 실패 입력 보존 유지 |
| 서비스 선택 | 전체 업무와 현재 영역의 등록 서비스를 한 목록에서 선택. 즐겨찾기 우선 정렬 |
| 서비스별 작업판 | 같은 공간에서 확인할 일·연결 프로젝트·가져온 기록을 전환. 긴 목록은 작업판 안에서 이동 |
| 연결·진단 관리 | 설정의 실제 서비스 관리·최근 결과 진단으로 이동. 자료 검색과 질문은 기존 별도 화면 이용 |

홈은 현재 회사·개인 영역 전체를 기준으로 시작한다. 과거에 저장된 프로젝트 선택으로 메모와 서비스가 사라지지 않는다. 서비스 선택과 보기 전환은 해당 화면 안의 상태이며 저장된 프로젝트 선택이나 업무 기록을 변경하지 않는다. 서비스·보기 전환 중 메모 초안은 유지된다. 영역이 바뀌면 다른 영역의 선택·초안·열린 기록을 섞지 않는다.

서비스별 수집 기록과 실행 요청은 실제 serviceId로 구분한다. 같은 프로젝트를 쓰는 서비스도 서로의 원본·실행 요청을 섞지 않는다. 프로젝트의 공통 할 일·요청은 ‘연결 프로젝트의 할 일/수정 요청’으로 출처를 밝힌다. 연결 없는 할 일·프로젝트는 전체 업무에서 확인할 수 있다. 프로젝트 연결이 없는 서비스에 공통 할 일을 임의로 붙이지 않는다.

업무 자료 상태는 서비스의 실제 연결·마지막 수집을 기준으로 표시한다. 웹 주소나 GitHub 점검 성공을 사업 업무 수집 성공으로 취급하지 않는다. 미연결은 연결 필요, 오래된 기록은 마지막 수집 기준, 오류는 마지막 정상 자료로 구분한다. 원본의 현재 업무가 0건이라고 추정하지 않는다. 읽기 창은 저장한 원문을 그대로 표시하고 등록된 안전한 원본 링크는 사용자 클릭으로 연다.

PC에서 상단 메모 영역과 하나의 서비스 작업판으로 페이지 길이를 제한한다. 서비스 목록과 작업판의 긴 내용은 각 영역 안에서 이동한다. 좁은 화면은 같은 순서로 배치하고 서비스 목록을 가로로 선택한다. 보기 탭은 방향키·Home·End로 전환하며 초점/선택 상태와 패널 관계를 제공한다. 입력·버튼·모달과 모든 저장 기록에 키보드로 접근할 수 있어야 한다.

기존 IndexedDB·서버 저장 형식, 파일, 계정·기기 승인, CAS와 실행 권한은 변경하지 않는다. 홈 열기·서비스 선택·읽기만으로 동기화나 새 작업을 요청하지 않는다. 사용자 기록을 테스트·공개 GitHub 자료로 쓰지 않는다. 기존 시트 목록 재발 방지 수정(Issue #98)도 같은 PR의 검증에 포함한다.
