# 업무실 사용 흐름 — 2026-10-23

메모를 작성하는 곳에서 저장한 기록을 바로 찾고, 확인한 내용을 다음 작업으로 이어갈 수 있어야 한다. 기존의 접힌 최근 메모와 30개 목록 제한은 기록을 다시 확인하기 어렵게 만들었다.

| 영역 | 기본 화면과 행동 |
| --- | --- |
| 범위·저장 상태 | 회사/개인, 선택 프로젝트, 저장 대기·오류를 계속 표시 |
| 메모·기록 | PC는 입력과 저장 목록을 나란히, 휴대폰은 같은 카드 안에 연속 배치. 저장 목록·검색·전체 보기 항상 노출 |
| 저장한 메모 | 내용·프로젝트 이름 검색, 수정 시각, 전문 읽기. 목록은 작은 페이지로 나누되 모든 기록 접근 가능 |
| 지금 확인할 일·프로젝트 | PC는 나란히 배치하고 휴대폰은 순서대로 배치. 실제 요청 상태와 단계별 이어가기 유지 |
| 자주 쓰는 서비스 | 등록 주소를 사용자 클릭으로 열기 |
| 연결·자료 관리 | 자주 쓰는 흐름 아래에서 진단·기록을 펼쳐보기 |

업무실 바로가기는 메모·할 일·프로젝트·서비스에 바로 이동한다. 별도 **메모** 메뉴 `/memos`는 모든 저장 기록을 찾아보는 곳이며, 기존 **맥락** `/notes`는 누적 배경·기준·결정과 이력을 유지한다. 저장 기록 확인과 맥락 편집을 구분한다.

업무실과 맥락의 메모 목록은 내용과 프로젝트 이름을 검색하며 회사/개인·프로젝트 범위를 먼저 적용한다. 범위 밖에 같은 영역의 메모가 있으면 개수와 전체 보기 이동을 안내한다. `/memos`는 현재 회사·개인 영역의 모든 프로젝트부터 보여주고, 이 화면에서만 적용되는 프로젝트 필터로 좁힌다. 필터는 업무실의 저장된 프로젝트 선택을 변경하지 않고 다시 열면 전체로 시작한다.

검색·페이지 이동·읽기는 기록을 수정하거나 서버 작업을 만들지 않는다. 읽기 창에서는 원문을 그대로 보여주고 Escape/닫기로 목록에 돌아오며, 입력 중인 메모는 그대로 유지한다. 새 메모 저장 성공 후 검색/페이지를 초기화해 새 기록을 바로 보여준다. 저장 실패 시 입력 유지와 중복 제출 방지는 기존 계약을 유지한다. 빈 목록은 현재 표시 범위의 상태이며 데이터 삭제의 증거로 취급하지 않는다. 저장 위치 확인은 기존 설정의 읽기 전용 진단으로 연결하고, 복구·가져오기는 그 확인과 구분한다.

저장 데이터, IndexedDB 버전, 파일, 계정·기기 승인, 서버 CAS와 실행기 동작은 변경하지 않는다. 새 외부 검색 서비스나 모델 호출은 없다. 검색 인덱스·내용을 별도 서버나 URL에 보내지 않는다. 사용자 기록은 공개 GitHub 검증 자료로 사용하지 않는다.
