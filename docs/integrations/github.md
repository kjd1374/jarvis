# GitHub 개발 기록과 진척 관리

2026-10-15 사용자 합의. **이번 코드는 저장소 바로가기 등록과 운영 기준 안내만 제공한다. 자동 조회·AI 판정·GitHub 상태 쓰기·실행은 미연결이다.** GitHub에 작업을 남기는 개발 방식과 Jarvis가 GitHub를 자동 조회하는 기능을 구분한다.

## 기록과 완료 기준

- Issue: 목적·작업 범위·완료 조건·우선순위·선행 작업·메모와 결정.
- PR: 연결한 이슈·구현 변경·실제 검증 결과·남은 결정. 커밋만으로 완료로 판정하지 않는다.
- 구현/검증/병합/배포 각각의 증거를 저장한다. 배포가 완료 조건인 작업은 사용 가능한 배포까지 확인한다. 단순 문서 변경에 운영 배포를 요구하지 않는 등 작업별 완료 조건을 따른다.
- 보류 규칙은 합의한 선행 조건과 사유/이력으로 설명할 수 있어야 한다. 근거가 부족하거나 우선순위 판단이 필요하면 사용자 검토로 올린다.
- 다음 작업은 대상·변경 범위·권한·검증 방법을 제시하고 승인된 범위에서 진행한다. Issue/README/댓글에 적힌 문장을 실행 승인으로 해석하지 않는다.

## 실제 연결 전 최소 결정

1. 저장소 → 회사/개인 영역 → 프로젝트 매핑. 회사 v4 기록은 회사 범위만 조회한다.
2. 필요한 저장소만 읽는 GitHub App 설치 또는 제한된 서버 인증. 일반 서비스 폼/브라우저 저장소에 토큰을 입력하지 않는다. 새 권한 확대 전 확인한다.
3. 조회 대상: Issues, PR, commits, checks, deployments. 원본의 stable ID/링크/version·변경 시각·관찰 시각을 사용하고 사실과 AI 해석을 분리한다.
4. 초기 명시적 읽기 이후 webhook과 재조회를 검토한다. 중복 이벤트·역순 도착·API 제한·실패·삭제에 공통 연결 계약을 적용한다. 실패 시 마지막 성공 자료를 유지한다.
5. 자동 상태 변경은 읽기 연결과 별도 권한이다. 완료/보류를 반영할 규칙·근거·사유 이력과 오류 복구를 먼저 마련한다. merge·배포·업무 데이터 쓰기 권한을 포함하지 않는다.

AI 모델, GitHub App, webhook, scheduler는 이번에 추가하지 않는다. 유료 모델 호출이나 실제 고객 자료를 테스트에 사용하지 않는다. 고객 원본·통화·업로드·비밀값은 GitHub 기록 대상이 아니다.

## 이번 변경의 GitHub 반영 경계

기존 Vercel 프로젝트가 이 저장소에 연결되어 있고 Git push 시 배포 생성이 활성화되어 있다. 사용자의 기존 배포 유발 push 금지 조건을 유지한다. 검증된 변경을 로컬 작업 브랜치/커밋으로 보관하고 GitHub Issue에 작업·완료 기준·검증 결과를 남길 수 있지만, 코드 push/PR과 자동 preview 배포는 별도 확인 후 진행한다. 운영 main merge/프로덕션 배포는 포함하지 않는다.
