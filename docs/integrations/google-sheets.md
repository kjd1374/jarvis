# 구글 시트 연결 계획

2026-10-15 사용자 요청을 제품 기준에 반영했다. **현재는 실제 시트 주소를 서비스/프로젝트에 저장하고 원본을 새 탭으로 여는 기능만 제공한다. Google 인증·읽기·쓰기·iframe 편집은 구현하지 않았다.**

## 목표 흐름

여러 시트의 미처리 업무 → Jarvis 통합 목록 → 항목을 보고 입력 → 변경 내용을 확인하고 보내기 → 원본의 지정 탭·열에 기록 → 재조회해 결과 확인. 시트가 원본이고 Jarvis는 필요한 정보와 참조를 보관한다.

## 시트 하나부터 확인할 사항

- 소속 회사/개인 영역·프로젝트, 문서 ID와 탭 ID, 열 이름·자료형, 읽을 행/업무 상태 조건.
- 정렬·행 삽입으로 변하지 않는 고유 항목 ID. 현재 행 번호만으로 쓰기 대상을 정하지 않는다.
- 입력을 허용할 열과 작업별 값 검증, 수식/보호된 셀 처리, 사용자에게 보여줄 원본과 변경 예정 값.
- 읽기 인증을 먼저 검토하고, 쓰기 권한은 별도 확인한다. 서버만 자격 증명을 보관하며 폼/브라우저/URL에 비밀값을 남기지 않는다.
- 전송 직전 원본을 재조회해 기준값과 다르면 재확인한다. 전송 후 다시 읽어 성공을 확인한다. 일반 Sheets API에 데이터베이스 수준의 CAS를 보장한다고 주장하지 않는다. 여러 편집자의 동시 쓰기 기준은 실제 시트에 맞춰 결정한다.
- 중복 전송 방지, 작업 결과/실패/재시도 이력, API 제한과 일시 오류 처리. 실패를 완료나 항목 삭제로 해석하지 않는다.
- Jarvis에서 사용자가 확인한 이력은 따로 저장한다. Google Sheets에서 과거 어떤 행을 사용자가 읽었는지 알 수 있다고 가정하지 않는다. 미처리 여부는 원본의 업무 상태 기준으로 정의한다.

비공개 시트 iframe은 Google 로그인/브라우저 정책에 따라 편집이 제한될 수 있으므로 현재 대안은 원본 새 탭 열기다. 실제로 읽을 시트와 허용 열을 확인하기 전 임의의 쓰기 API나 연결된 것처럼 보이는 결과를 제공하지 않는다. 테스트는 합성 시트/응답으로 진행하고 실제 시트 변경 검증은 별도로 승인된 테스트 범위에서만 수행한다.
